# Candy Lab — בוטים שאוספים סוכריות ומתרחקים מאנשים (Roblox)

פרויקט לימוד ל-Roblox Studio, **למשחק שלך**. ממתקים נוצרים במפה, ובוטי NPC אוספים אותם. כל בוט בוחר את הסוכרייה שנמצאת באזור הכי ריק, הולך אליה עם Pathfinding ובורח כששחקן מתקרב. בצד השרת יש Anti-Cheat שמזהה את שתי הטכניקות של סקריפט auto-farm מוזרק: טלפורט בין ממתקים, ו-touch מרחוק.

זה לא סקריפט להזרקה למשחקים של אחרים (כמו Murder Mystery 2), והוא לא יעבוד שם. הקוד רץ בשרת של המשחק שלך.

## הרצה

**עם Rojo (מומלץ):** גרסת Rojo נעולה ב-`rokit.toml`. פעם אחת, מתוך תיקיית ה-repo:

```
rokit install
rojo plugin install
```

אחר כך, בכל פעם: `rojo serve`, וב-Studio ‏**Plugins ← Rojo ← Connect**. (התקנת Rokit: https://github.com/rojo-rbx/rokit)

**משחק קיים:** פותחים את המשחק ב-Studio ומתחברים באותו אופן. Rojo מחליף רק את התיקיות `ReplicatedStorage.Shared` ו-`ServerScriptService.Server`, ושאר המשחק לא משתנה. אם במשחק כבר יש אובייקטים בשמות האלה, הם יוחלפו, ולכן כדאי לבדוק לפני החיבור. אחרי הבדיקה שומרים ומפרסמים כרגיל (**File ← Publish to Roblox**), והקוד נשמר בתוך המשחק.

**בלי Rojo:** ב-Studio יוצרים `Folder` בשם `Shared` תחת `ReplicatedStorage` ו-`Folder` בשם `Server` תחת `ServerScriptService`. כל קובץ `.luau` הופך ל-`ModuleScript` באותו שם (בלי הסיומת). `Main.server.luau` הופך ל-`Script` בשם `Main`.

**המפה:** אפשר ליצור `Folder` בשם `CandySpawns` ב-`workspace` ולשים בו Parts שמסמנים אזורים: קופסאות שמכסות את אזור ההליכה מהרצפה ועד מתחת לתקרה, עם `Anchored`, `Transparency = 1` ו-`CanCollide` כבוי. הקרן יורדת מראש הקופסה, כך שגגות לא מפריעים. ממתקים ובוטים יופיעו רק בתוכם. בלי התיקייה, הם יופיעו בריבוע של 180×180 סביב מרכז המפה (מתאים ל-Baseplate). השמירה ב-Studio דורשת את ההגדרה Game Settings ← Security ← Enable Studio Access to API Services. בלי ההגדרה המשחק עובד, אבל לא שומר.

## איך הבוט מחליט

בכל סבב, ב-`think` שבקובץ `CandyBots.luau`:

1. **בריחה:** אם שחקן נמצא בתוך `FleeRadius` (20), הבוט מחשב כיוון בריחה. זה סכום הווקטורים שמתרחקים מכל שחקן קרוב, וככל ששחקן קרוב יותר הוא דוחף חזק יותר (1/מרחק). הבוט הולך `FleeDistance` (35) בכיוון הזה. אם אין שם רצפה (קצה המפה), הוא מנסה זוויות של 45°, 90° ו-135° לכל צד.
2. **בחירת סוכרייה:** הבוט מדלג על כל סוכרייה שנמצאת פחות מ-`SafeRadius` (30) משחקן. השאר מקבלות ניקוד:
   `ניקוד = min(מרחק מהשחקן הקרוב, SafetyCap) − DistanceWeight × מרחק מהבוט`
   כלומר: עדיף אזור ריק, אבל לא במחיר של הליכה לצד השני של המפה. מעל `SafetyCap` אזור ריק יותר כבר לא מוסיף ניקוד.
3. **הליכה עם ביטול:** כל 0.1 שניות בדרך הבוט בודק שלוש עצירות: הסוכרייה נעלמה, שחקן התקרב לבוט, או שחקן התקרב לסוכרייה. בכל אחד מהמקרים הוא עוצר ומחליט מחדש.
4. **אין סוכרייה בטוחה:** הבוט זז לאזור הריק ביותר ומחכה שם.

שני בוטים לא רודפים אחרי אותה סוכרייה, כי יש `claims`. סוכרייה שהבוט לא הצליח להגיע אליה נפסלת עבורו ל-10 שניות.

## הצד של הסייבר: למה auto-farm מוזרק נתפס

סקריפט auto-farm רץ אצל הלקוח. הוא יכול לעשות רק מה שהלקוח יכול לעשות: להזיז את הדמות (גם בטלפורט) ולדווח "נגעתי בחפץ". לכן מה שהשרת לא בודק, אפשר לזייף:

| טכניקת ה-exploit | הבדיקה בשרת (`AntiCheat.luau`) |
|---|---|
| טלפורט מסוכרייה לסוכרייה | דגימת מיקום כל 0.5 שניות; מהירות אופקית מעל 40 נחשבת strike |
| `firetouchinterest`, כלומר נגיעה מזויפת מרחוק | בכל איסוף נבדק המרחק בין `HumanoidRootPart` לסוכרייה (עד 10) |
| איסוף בקצב לא אנושי | לפחות 0.15 שניות בין איסופים |
| עריכת מספר הממתקים אצל הלקוח | הערך נשמר רק ב-`leaderstats` שבשרת ונשמר מהשרת. שינוי אצל הלקוח לא משתכפל לשרת |

אחרי strike, האיסוף מושבת ל-5 שניות ונרשמת אזהרה. כדי להעיף שחקן, מגדירים `KickAtStrikes`. אם המשחק עצמו מזיז שחקן (סבב חדש, טלפורט של אדמין), צריך לקרוא ל-`AntiCheat.allowTeleport(player)` לפני ההזזה, כדי שזה לא ייחשב strike.

הבוטים עצמם עוברים את הבדיקות, כי השרת מריץ אותם (`SetNetworkOwner(nil)`) והם הולכים במהירות רגילה.

## רעיונות להמשך

- תפקיד Murderer (שחקן עם Attribute `Role`) שהבוטים בורחים ממנו ברדיוס כפול.
- `PathfindingModifier` לאזורים שהבוטים צריכים להימנע מהם.
- תרגיל: לכתוב בצד הלקוח, ב-Studio בלבד, ניסוי שמזיז את הדמות מהר, ולראות את ה-strike בפלט.
